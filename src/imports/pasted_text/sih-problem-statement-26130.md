Create a complete, high-fidelity, production-quality UI/UX prototype for SIH Problem Statement 26130 — an AI-Assisted Industrial Approval, Compliance and Government Support Intelligence Platform for Maharashtra.

PROJECT CONCEPT

The platform is an intelligent orchestration layer around existing government single-window ecosystems such as MAITRI, MIDC Single Window and NSWS.

IMPORTANT:
This is NOT another generic single-window portal.
Do NOT design it as a replacement for existing government portals.

The platform should help industrial applicants understand:
• which approvals apply to their project
• which departments are involved
• what documents are required
• whether documents are ready
• which approvals depend on others
• which approvals can run in parallel
• where delays are likely
• which SLA deadlines are at risk
• when inspections should be coordinated
• when escalation is required
• what compliance and renewals are upcoming
• which government incentives/support schemes may apply

Government officers should get:
• workflow visibility
• SLA-risk visibility
• bottleneck detection
• dependency analysis
• inspection coordination
• escalation management
• compliance monitoring
• analytics and policy insights

CORE PRODUCT IDEA

Transform:

Business Profile
→ Approval Discovery
→ Personalised Approval Roadmap
→ Document & Compliance Readiness
→ Dependency & Parallel Workflow

IMPORTANT UX RULES
==================================================

1. Do NOT make this look like another generic government portal.

2. The central visual metaphor should be:
“Intelligence Layer + Workflow Orchestration”

3. Show the relationship:

EXISTING ECOSYSTEM
MAITRI • MIDC • NSWS • DEPARTMENT SYSTEMS

↓

NEXROUTE INTELLIGENCE

↓

DISCOVER
VALIDATE
COORDINATE
PREDICT
ESCALATE
COMPLY

4. Use progressive disclosure.
Applicants should see simple information first and deeper regulatory/workflow details when needed.

5. Government dashboards can be information-dense.
Applicant screens should be simpler.

6. Every AI-generated recommendation should have an explanation.

7. Every regulatory answer should show its source.

8. Predictions should be presented as risk indicators, not guaranteed outcomes.

9. Do not invent official government APIs or claim live integration.
Use realistic demo/curated data where necessary and label it clearly.

10. Never expose sensitive applicant information to unauthorized roles.

11. Use RBAC-aware navigation and data visibility.

12. Critical actions must use confirmation dialogs.

13. Make the dependency graph and SLA intelligence visually impressive because these are major differentiators.

14. Do not overload every screen with AI.
AI should appear where it provides clear value.

15. The interface must be suitable for a government evaluation/demo.
